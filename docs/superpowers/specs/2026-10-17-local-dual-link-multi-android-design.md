# 本地双通道与多安卓连接设计

状态：用户已于 2026-10-17 回复“开始”批准此首版范围，并回复“执行”选择 Native 实施。设备域注册表、共享 BLE Radio、多设备路由与提醒已进入回归；正在完成整段审查和构建，尚未完成两台安卓真机验收、安装、提交或发布。用户已授权保留数据覆盖安装，第二台安卓地址待提供；不重启本机 Xcode 测试服务。

## 1. 已确认的使用规则

- 设置中增加 VoWLAN＋VoBLE 双通道选项，既有单 VoWLAN、单蓝牙、云端、自动模式继续保留。
- 一个 iOS AirSIM 可同时连接多台已配对安卓，而非仅保存多条配对历史、切换时才连接。
- 拨出时由用户指定安卓设备；默认拨号设备只是拨出偏好，不过滤其他设备的来电。
- 来电操作始终指向真正来电的安卓，不因默认设备或当前列表选择变化而转移。
- 已在安卓 A 通话时，安卓 B 来电只做提醒，不打断 A，不自动接听或挂断任何一台。

以下首版范围与技术取舍由实现者提出，并随用户批准的完整设计进入计划；实现细节仍按下文授权边界处理。

## 2. 首版范围与明确不做的事

新增模式暂命名为“本地双通道”：同一安卓的 VoWLAN 与 VoBLE 同时保持认证控制连接，不强制开启 Relay 或 PushKit。通话建立前，同一设备优先 VoWLAN，次选 VoBLE；只有一条链路持有音频，不复制 PCM 同时播放。多安卓待机首先适用于单蓝牙与本地双通道，纯 VoWLAN保留原有能力并复用设备归属模型。

首版不承诺通话途中 VoWLAN↔VoBLE 无缝迁移。继续保持仓库现有“本通话传输锁定”的安全契约：当前链路失效，只执行该传输既有、绑定同一通话及 generation 的恢复；恢复失败，明确提示本次通话失效。下一通可选择另一条可用链路，不偷偷重拨、不切换到另一台安卓。无缝迁移需要独立的跨传输媒体租约、双端切换确认和故障回滚协议，不附带在本轮实现中。

首版仅允许 iPhone 持有一路通话音频，不做跨安卓保持／会议／混音，也不新增云端多设备推送协议、Relay 部署或 Apple Watch 直连多安卓。已有云端与自动模式保持其既有行为；新增模式不变成现有 Wi-Fi 功能的必需条件。

验收至少覆盖两台安卓真正同时连接、待机和接收来电事件。更多连接的资源限制由实测决定，不以保存设备数量冒充并发容量，也不承诺无限连接。

## 3. 拨出、来电与并发提醒

### 指定设备拨出

拨号操作开始时快照用户所选 agentID；只在这台设备内选择允许的可用传输。选中设备离线时明确不可拨，不借另一台在线设备拨出。双通道的“可用”必须来自真实认证、控制及媒体能力，不以存在配对缓存或 HTTP 200 代替。

通话开始后，设备、通话标识和传输的归属不随默认拨号设备改变。挂断、拒接、DTMF、音频启动与最低音量策略都使用这一归属。

### 空闲时接听来电

来电带有经认证的来源设备。只有用户明确接听后，才为该设备获取唯一的音频所有权。不同安卓的原始 callID、号码可能相同，不能以其一单独去重。多个空闲来电同时出现时均保留来源；用户接听一个后，其余转为“其他设备来电”提醒。

### 通话中的其他设备来电

1. A 继续通话，音频、CallKit 主通话和灵动岛主计时均不被 B 替换。
2. B 的首个有效响铃事件生成一次来源明确的提醒，包含设备名与来电人信息，遵守系统隐私设置。默认采用视觉提示与系统允许的轻触反馈，不往 A 的 PCM 混入响铃音，不以每次状态刷新重复提醒。
3. B 自己继续响铃；AirSIM 不因 iPhone 忙而发送拒接、挂断、接听、PCM 启动或受控降音量命令。
4. A 结束后，重新核对 B 是否仍响铃；仍响铃时允许用户主动接听，不自动接听。若有多个仍响铃设备，保留全部来源，等待用户选择，不自动挑选一个。
5. B 已结束时撤销其提醒，并正确记录其未接／已在安卓处理的实际终态；B 的结束事件不能结束 A。
6. 重复事件、断线重连与迟到响铃不能恢复已经结束的提醒。通知操作必须携带来源设备和通话标识，操作前验证当前状态；不通过当前全局选中设备重新推断目标。

锁屏／后台提醒以 iOS 实际授权和系统调度为限，不能承诺强退后离线本地来电一定唤醒。通知未获授权时，前台提示与通话记录仍可用，不强制用户授权。

## 4. 会话隔离与现有代码调整方向

目前 `VoBLECentralController` 持有一个 peripheral、一个活动认证会话和一组待回应命令；`CallKitController` 与 `AppModel` 的主要通话状态同样面向单当前通话。`VoBLEPairingStore` 已按 identity 保存 Keychain 凭据，多凭据并不等于已实现多活动连接。

本轮应拆分以下职责，具体类型名与文件边界留给实施计划：

- 一个共享蓝牙发现／系统恢复入口管理多台外设，避免每台设备各自持续全量扫描。
- 每个经认证的 agentID 拥有独立的外设、认证状态、加密会话、消息分片器、重放窗口、命令 continuation／超时、重连代次和当前设备资料。
- 设备级协调层把同一 agentID 的 VoWLAN 和 VoBLE 汇合为两条候选链路。不得靠显示名、电话号码或外围设备 UUID 猜测两条链路属于同一台设备。
- 通话键至少包含 `(agentID, callID, generation)`，另建立与系统 CallKit UUID 的明确映射；这里的 generation 是协调层统一的通话代次，不能直接把 BLE 会话代次与 VoWLAN 连接代次视为相等。两条传输各自的重连代次独立保留，以安卓权威通话 ID 和经认证的临时 ID 映射归并到同一通话；双传输上报同一来电只能产生一个来电实体。
- 全局音频仲裁器仅允许一个活动媒体租约；其他设备的控制连接继续待机，不为“在线”启动 PCM。
- 蓝牙解析、认证、Keychain I/O 与 PCM 调度继续离开 UI 主线程。UI 只接收合并后的设备状态，不能恢复此前扫描引起的卡顿。

已有全局 Android 绑定用于默认拨出上下文时，不能同时作为来电订阅过滤条件；删除／禁用设备则必须仍阻止其自动重连。仅删除某一设备时取消其连接、凭据、手动路由和待回应任务，不影响其他设备。

VoWLAN 当前有全局凭据入口：新设备注册与路由必须具有明确的设备—凭据关联，不能一次配对覆盖其他设备正在使用的认证材料。保留旧安装的凭据及现有连接；只有成功认证的既有绑定或用户明确重新配对，才可迁移到设备级记录，禁止仅凭 Bonjour 名称复制旧凭据给新设备。BLE 既有 identity Keychain 记录继续兼容。

升级兼容补充：未设置“默认拨出设备”的旧安装也可能已有有效配对。此时允许用旧密钥对候选设备重新做 nonce 绑定的身份 HMAC 校验，成功后才保存该 `agent_id` 的设备凭据；若已指定另一台默认设备，不对候选设备使用全局旧密钥。广播名称、号码或 HTTP 200 均不是迁移证明。

本轮不顺带设计多设备短信产品界面；但短信等任何由连接层送达的事件均需保留真实来源，已有短信发送操作的目标须在提交时锁定，不能被后台另一台设备的连接／来电改写。不得因本轮改动丢弃既有短信记录或恢复“点不进会话”的问题。

## 5. CallKit、后台与安全边界

双通道不依赖云端推送；CallKit 是本机通话系统集成，不等于开启 Relay。新增模式不得沿用“本地模式”旧布尔值而误关蓝牙通话所需的 CallKit，也不得为双待启动新的 Relay 查询／注册定时器。

本地 B 来电在 A 通话期间走提醒分支，不覆盖 A 的系统通话对象。既有云端路径若收到要求上报的真实 VoIP Push，仍必须按 Apple 规定上报 CallKit，不能用本地通知替代或忽略 PushKit 完成回调；相关失败也不能转化为给错误安卓发送挂断。此兼容分支必须单独回归，不在本轮承诺跨云端的纯本地式提醒外观。

每台设备独立认证；取消配对、重连恢复、双通道合并都不得跳过认证。保留 HMAC／时间戳／nonce、BLE 加密及重放保护。沿用受控音量归属检查，只有实际被接听并拥有就绪远程音频的唯一通话才接管输出；待机 B 不受影响。日志只记录脱敏状态、代次和故障分类，不记录密钥、号码全文、短信正文或 PCM。

## 6. 迁移与交付边界

- 增量增加模式，旧设置值和旧配对记录仍可读取；不重置现有用户模式或静默改为双通道。
- 新模式同时启用两条本地控制链路，离开模式时按所有权释放资源；活动通话不因模式设置改变而转移到别的设备／链路。
- 继续兼容仅有一种链路的安卓，不虚报“双通道就绪”。需要新双端能力的行为须明确协商，旧端不可用时说明原因，不伪造在线。
- 先形成实施计划，分层迁移设备会话、来电归属及提示策略，再接入模式和展示；每层保留可回归的旧功能。
- 此文档不是安装、提交、push、Release、TestFlight 或生产 Relay 部署授权。实际安装与发布另按用户明确要求执行。

## 7. 验收

自动化应覆盖：两设备活动连接互不覆盖；来源相同号码／callID 不碰撞；同设备双传输事件去重；默认拨号设备与来电设备不同；所选设备离线不换机拨出；A 通话时 B 提醒、B 挂断不影响 A；A 结束后 B 仍响／已结束的两种情况；迟到回复和旧代次回调；删除单设备不影响另一台；已配对但未认证不能拨号；仅当前 PCM 所有者触发音量接管；旧模式及短信会话导航不回归。

真机至少用一个 iPhone、两台安卓验证：两台同时待机，分别拨出／来电，A 通话中呼入 B，两台同号码显示的归属，锁屏提醒，Wi-Fi／蓝牙断开重连，重复事件不重复响铃，无串音／回声和 UI 卡顿。双通道还需验证无 Wi-Fi 时蓝牙可建立下一通、无蓝牙时 VoWLAN 可建立下一通，以及当前通话不发生未经协议确认的链路迁移。测试结果须区分用户已确认、自动化通过和未执行场景。
