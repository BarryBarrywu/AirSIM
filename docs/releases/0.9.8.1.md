# AirSIM Apps v0.9.8.1 — 应用更新检测与音频兼容诊断

日期：2026-10-19（Asia/Shanghai）。Android Standalone／AVF Bridge `0.9.8.1 (95)`，iOS／Watch／Live Activity `0.9.8 (95)`，从 `VoBLE` 分支发布。推荐 Android 10–13 用户安装／升级 Standalone，保留此前旧系统 API、短信与蓝牙认证修复；不能将推荐安装理解为所有 OEM 音频均已验收。

## 更新内容

- iOS 和 Android 首次安装／升级后展示包内更新说明；「设置 → 关于」可以重看说明、手动检查应用新版。按版本名＋build/versionCode 保存已读标记，离线也可查看。
- 前台空闲时每日最多自动检查一次应用更新，失败也限频，手动与自动共用单个在途请求。不访问 Relay、不增加云端状态轮询、不自动下载或安装。
- 区分 Standalone APK、AVF Bridge APK 与 iOS IPA，排除 Linux Agent、草稿、预发布及未上传完成的资源。iOS 兼容四段热修复发布 tag 与三段 App 版本，只按 IPA 自己的 build 判断，不猜测 Android versionCode。
- 检查失败不会误报「最新版」；iOS 明确区分 TestFlight／侧载提示。更新提示避让通话，异步结果在后台或通话中先保留；Android Activity 重建后仍可接收检查结果。首次配对引导被来电打断不再误记为完成。
- 修复 iOS 云端待机状态：查询调度时间与已确认结果时间分开记录，切后台不再把刚确认的云端在线状态立即覆盖成模块离线；保留最近确认结果不代表实时持续探测。不新增 Relay 定时请求。
- Android 针对臻情 Zhenqing 的下行近乎静音日志，增加最低非零音量策略并保持通话输出流未静音；仅限该厂商匹配，三星与其他机型策略不变。挂断／媒体断开仍恢复原状态，Watchdog 不再误修复成静音。最低档不等于完全静音。
- Android PCM 初始化失败时及时释放已经创建的采集／播放资源，停止失败仍释放，不让清理异常覆盖原始原因。TXT 保留启动阶段、稳定错误码、异常类别和有界失败计数，区分权限、蜂窝上行路由、端点初始化与 READY 握手失败。
- 保留 0.9.8（92）已发布的 VoBLE 音频图初始化顺序修复；不将新诊断字段当作已修复所有系统蜂窝音频能力的证据。

## 下载与安装

- `AirSIM-Android-Standalone-0.9.8.1-build95-Android10-13.apk`：推荐，单 APK 内置 Agent，不依赖 AVF Linux。
- `AirSIM-Android-AVF-0.9.8.1-build95-Android10-13.apk`：旧 AVF 部署的 Android Bridge，不是 Linux Agent Debian 更新。
- `AirSIM-iOS-0.9.8-build95-unsigned.ipa`：包含 Watch 与 Live Activity，需完整重签。
- `AirSIM-iOS-0.9.8-build95-sideload-unsigned.ipa`：不含 Watch、保留 Live Activity，仍须侧载工具重签。
- `SHA256SUMS.txt`、`LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.md`。

正式 APK 复用既有发布证书，可覆盖同包名、同签名安装。不要先卸载／清配对数据；Debug／第三方重签包不能直接用正式证书包覆盖。公开 IPA 不包含 Apple 签名或设备描述文件，不能直接安装或上传 TestFlight。维护者另用 Xcode 上传 production 构建；上传、Apple 处理、外测审核和测试者可更新分别核实。

## 验证与已知限制

功能候选已保留数据安装到 iPhone Air 与三星 Flip7并通过主 App 启动／进程复查；三星原生更新说明弹窗已确认。问题臻情／华为设备的真实双向声音、最新云端待机锁屏显示、其他 OEM、长时锁屏、多安卓与 Watch 仍须分别实测。此次不擅自拨打电话或发送短信。

臻情日志强烈提示输出静音会影响下行采集，但缺少该问题设备的 A/B 声学验证。华为 BLA-L29 Android 10 的日志只证明 PCM 在 READY 前失败，新版用于保留根因和防资源泄漏，不能承诺固件开放蜂窝音频。详情：[臻情日志](../zhenqing-android13-call-audio.md)、[PCM 启动失败](../android-pcm-startup-failures.md)、[应用更新](../app-updates.md)。

发布测试、产物签名和 Xcode 上传回执完成后追加记录；不能把未完成的 Apple 处理或外测状态写成已发布给测试者。此前 iOS 用例执行270项、零失败，但部分运行卡在 xcresult 收尾；本次保留用户当前测试服务环境，不重启服务，重新运行并如实记录结果。

本轮不新增 workflow、不合并 main、不部署生产 Relay，不发布新 AVF Linux Agent；Linux Agent v0.4.6 继续保留仓库 Latest，应用 Release 不设 Latest。
